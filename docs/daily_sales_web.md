# 每日预估销量

页面入口：`/#daily-sales`，接口 `GET /api/daily-sales?date=YYYY-MM-DD`。
每日销量批次优先读取北京时间今天、且 `sale_date=captured_date=今天` 的有效预估。今天尚未抓取到有效预估时，只回退到昨日抓取的昨日数据，并醒目提示“当前使用昨日数据，并非今日数据”；不自动回退到更早日期。两天均无有效数据时预估为空，只展示前7天参考并提示。手选历史日期后读取该业务日期的已保存快照，不自动换日；没有快照时提示点击“更新数据”生成。每天09:30补映射后的销量更新重新判定默认日期，此后的4小时库存更新沿用当天销量批次。当天尚无成功销量取数时，09:30补映射完成后可取数，后续白天服务端时点可补齐一次。

## 运行

复用当前用户 Windows `PGHOST/PGPORT/PGDATABASE/PGUSER/PGPASSWORD`，数据库必须为 `scrape_data`。凭据仅从环境或当前用户注册表读取，不写入项目和浏览器。Python依赖 `psycopg2-binary`。

看板PostgreSQL连接设为只读、可重复读；查询来源只执行SELECT。独立 n8n 流程单独写入 `public.community_plan_sku_mapping`，唯一平台商品ID防重复，已存在映射不覆盖；两者均不写原生产映射表。接口处于原网站认证边界内，日期参数校验，源查询超时45秒。普通打开、筛选、翻页、定时读取和重启后读取均不查询PG或Doris，只读取服务器持久快照；没有快照时提示手动更新，不自动回源。仅“更新数据”（`refresh=1`）或服务端定时任务取数，成功后原子替换快照；相同并发更新合并为一次，更新期间及失败后继续展示上次成功数据。默认快照同时保存业务日期别名，重启不丢失，无5分钟过期回源。


## 库存及预警

- 展示顺序：仓库、商品、云仓库存（本次滚动当日库存＋采购在途＋调拨在途）、当日预估、7日均销、预警。
- 2026-11-11 新口径：优先判断预估 > 云仓库存含在途，为红色“库存不足”；已知库存不足时，即使历史销量缺失也保留红色。预估 > 参考销量×3 且预估 < 云仓库存含在途，为黄色“库存紧张”；其余数据齐全且未触发以上条件为绿色“正常销售”。不足7天仍沿用已确认的单日最高销量作为参考，不改变7日口径。
- 严格比较，相等不触发：等于3倍参考销量且库存足够，或等于库存，归绿色；超过库存始终优先红色。必要数据缺失且未发现已知缺货则灰色“待核验”，库存未知时不把销量激增单独判红或判黄。数量不因预警规则变更而变化。
- 2026-11-11最新要求取消昨日固定库存基数。当前库存取用户`sql/inventory_web_user.sql`的“当日库存”：`ROUND(实时库存－待出库＋待入库,0)`，每次从当前`scm_warehous_manage`及当前调拨单取数。`sql/daily_sales_stock.sql`仅提取该SQL的当前库存部分，保留状态、节点、特殊仓及维表连接条件，不计算无关的期间消耗。它与原SQL逐仓库SKU核对后启用。无需读取昨日档案。2026-11-12按最新业务要求：库存源查询成功且仓库对应有效时，SKU无库存行、滚动库存为NULL或0均以0计算，再加采购和调拨在途并重算预警；负库存保留原值。库存源查询失败、整体为空或云仓未配置时仍视为不可用，刷新失败保留上次成功快照。

- 顶部保留两行定时安排：“库存定时09:00 / 13:00 / 17:00 / 21:00”和“销量定时每日09:30补映射后”，按北京时间显示。实际成功取数时间在展开的计算口径中查看，不能将手动取数时间伪装成定时完成时间。`sales_queried_at`记录PG销售批次时间，`inventory_queried_at`记录本次库存取数时间；`queried_at`记录组合快照更新。升级前快照以原`queried_at`作为销量批次时间。库存更新不改变销量日期、7天窗口、已换算数量、映射、缺失清单和来源时间。
